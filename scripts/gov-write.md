# /gov-write — 정부지원금 콘텐츠 자동 생성 파이프라인

키워드 하나를 받아서 검색어 수집 → Q1-Q4 분석 → 타이틀/H2 구성 → 컴포넌트 선택 → 글 작성 → 검증까지 자동으로 실행한다.

## 사용법
```
/gov-write 기초연금
```

---

## Phase 1: 검색어 수집

### 1-1. Playwright로 실제 검색어 수집
```bash
npx tsx scripts/collect-keywords.ts "기초연금"
```

결과: `scripts/output/기초연금.json`

### 1-2. 수집 데이터 읽고 확인
```
scripts/output/{keyword}.json 파일을 Read로 읽는다.
수집된 검색어 수가 최소 30개 이상인지 확인.
30개 미만이면 동의어를 추가하고 재수집.
```

### 1-3. 동의어 확장 (수동 보완)
수집된 검색어에서 동의어 패턴을 발견하면 synonymMap에 추가.
각 동의어로 재수집하여 누락 방지.

---

## Phase 2: Q1-Q4 필수 사고

수집된 검색어를 의도별로 분류한 뒤, 각 의도 그룹마다 Q1-Q4를 실행한다.

### Q1. 이 키워드를 검색하는 사람은 지금 어떤 상황인가?
- 수집된 검색어를 보고 **실제 검색 상황 3가지 이상** 도출
- 각 상황이 별도 스포크가 될 수 있는지 판단
- 예: "기초연금 신청 서류" → 곧 행정복지센터에 가려는 사람
- **서론 첫 문장에 이 상황을 반영**

### Q2. 이 글을 읽고 나서 할 수 있어야 하는 행동은?
- 각 스포크별로 **최종 행동 1개** 특정
- 그 행동의 **마지막 클릭 URL** 특정 (딥링크 CTA 목적지)
- 예: "복지로에서 기초연금 신청" → https://www.bokjiro.go.kr
- **타이틀 line2와 CTA 버튼 텍스트에 반영**

### Q3. 행동하려면 반드시 알아야 하는 정보는?
- 수집된 검색어 중 해당 스포크에 속하는 것 전부 나열
- 이것이 **H2 개수와 깊이를 결정**
- 수집 검색어에 없는 H2는 만들지 않는다

### Q4. 이 정보를 가장 잘 전달하는 형태는?
- 아래 **15개 컴포넌트** 중 선택
- 의도 분류에 따라 자동 추천하되, Q3 정보에 맞게 조정

## Phase 3: 타이틀·H2 구성

### 타이틀 규칙
1. **line1 = 실제 검색어** 그대로 (최소 수정)
2. **line2 = Q2 행동의 결과/이익** (자연스러운 문장)
3. 연결: 자연 문장 또는 없음 (파이프·대시 금지)
4. **금지어**: 총정리, 정리, 완벽정리, ㅡ

### H2 규칙
1. **반드시 수집된 검색어 or PAA에서** 가져온다
2. 내가 만든 소제목 **금지**
3. 검색어가 질문형이면 **질문 그대로** 사용
4. 검색어가 명사형이면 **자연 질문으로 변환** ("~는 얼마인가?")
5. H2 순서 = 검색 의도 우선순위 (가장 많이 검색되는 것부터)

### 스포크 분리 기준
- 검색 의도가 **다르면** 별도 스포크
- 같은 의도 안에서 검색어가 **5개 이상**이면 별도 스포크 고려
- 하나의 스포크에 H2는 **3~6개**

## Phase 4: 컴포넌트 선택

### 15개 컴포넌트 목록

| ID | 이름 | 트리거 (언제 자동 선택되나) |
|----|------|--------------------------|
| C01 | 자격 체커 | 의도=condition + "받을 수 있나", "자격", "대상" |
| C02 | 소득인정액 계산기 | 의도=calculate + "소득인정액", "계산" |
| C03 | 지급액 시뮬레이터 | 의도=calculate + "얼마", "금액", "수령액" |
| C04 | 비교표 | 의도=compare + "차이", "vs", "다른" |
| C05 | 기준표 | 의도=condition + "기준", "이하", "이상", "한도" |
| C06 | 금액표 | "금액", "단독", "부부", "가구" |
| C07 | 서류 체크리스트 | 의도=action + "서류", "준비물", "가져갈 것" |
| C08 | 신청 경로 탭 | 의도=action + "신청", "어디서", "방법" |
| C09 | 타임라인 | "절차", "순서", "언제", "지급일" |
| C10 | 경고 박스 | "제외", "안 되는", "주의", "실수" |
| C11 | 상황 분기 | "~하면", "~인 경우", "~이면" |
| C12 | 딥링크 CTA | 모든 스포크 (Q2 행동의 마지막 클릭) |
| C13 | 요약 카드 | 모든 스포크 최상단 (5초 답변) |
| C14 | FAQ 아코디언 | PAA 질문 3개 이상 |
| C15 | 관련 스포크 링크 | 모든 스포크 하단 |

### 자동 선택 로직
```
필수 컴포넌트: C12(딥링크) + C13(요약) + C14(FAQ) + C15(관련링크)
+ 의도별 추가:
  condition → C01(자격체커) + C05(기준표)
  calculate → C02(계산기) or C03(시뮬레이터) + C06(금액표)
  action    → C07(서류체크리스트) + C08(신청경로탭)
  compare   → C04(비교표)
  confirm   → C11(상황분기)
  question  → C14(FAQ 강화)
+ 경고 조건: 제외 대상/주의사항 → C10(경고박스)
+ 시간 조건: 절차/일정 → C09(타임라인)
```

## Phase 5: 글 작성

### 구조
```
[기] 서론 — Q1 상황 공감 (첫 문장)
[승] C13 요약카드 — 5초 안에 핵심 답변
[전] H2 섹션들 — 수집 검색어 질문에 하나씩 답변
     각 H2 안에 Q4로 선택된 컴포넌트 배치
     광고 슬롯: H2 2~3개마다 1개
[결] Q2 행동 유도 — C12 딥링크 CTA
     C14 FAQ
     C15 관련 스포크 링크
```

### 문체 규칙 (quality-config 연동)
- "~에 대해 알아보겠습니다" 금지
- "또한", "결론적으로", "다양한" 금지
- 3문장 연속 같은 어미 금지
- 3문장 연속 같은 단어 시작 금지
- 전문용어 뒤 반드시 괄호 설명

### 소스 규칙
- 모든 숫자/기준은 gonggam.korea.kr 또는 공식 소스에서만
- 소스에 없는 정보 → 사용자에게 요청
- source 필드에 출처 URL 반드시 기재

## Phase 6: 검증 에이전트

글 작성 완료 후 자동 실행. 12개 항목 전수 검사.

### V1. 타이틀 검색어 일치
- H1의 메인 키워드가 `scripts/output/{keyword}.json`의 수집 검색어에 존재하는가
- PASS: 완전 일치 또는 부분 일치
- FAIL: 수집 검색어에 없는 표현 사용

### V2. H2 출처 검증
- 모든 H2가 수집 검색어 or PAA에 근거하는가
- 매칭되지 않는 H2는 FAIL + 어떤 H2가 문제인지 리포트

### V3. Q1 공감 검증
- 서론 첫 문장이 독자의 실제 상황을 짚는가
- "~하시죠?", "~모르겠죠?", "~궁금하신" 등 공감 표현 포함 여부
- 제3자 시점("이 제도는~")으로 시작하면 FAIL

### V4. Q2 행동 완결
- CTA 버튼이 존재하는가
- CTA의 href가 실제 신청/확인 URL로 연결되는가
- "자세한 내용은 확인하세요" 같은 모호한 CTA면 FAIL

### V5. Q3 정보 완결
- 수집 검색어 중 해당 스포크 의도에 속하는 것이 본문에서 답변되었는가
- 답변되지 않은 검색어 리포트

### V6. Q4 컴포넌트 일치
- 의도 분류에 따른 필수 컴포넌트가 사용되었는가
- condition 의도인데 자격체커 없으면 FAIL
- calculate 의도인데 계산기/시뮬레이터 없으면 FAIL

### V7. 요약카드 존재
- 글 최상단에 answer-box 또는 요약카드가 있는가
- 5초 안에 읽을 수 있는 분량인가 (3문장 이하)

### V8. 소스 팩트 일치
- 본문의 숫자(금액, 나이, 기준)가 소스 데이터와 일치하는가
- source-data 파일이 있으면 자동 대조
- 없으면 WARNING (수동 확인 필요)

### V9. 문체 검사
- AI냄새 단어 사용 여부
- 같은 어미 3연속
- "~에 대해 알아보겠습니다" 류 filler 문장
- CLAUDE.md 문체 규칙 위반 여부

### V10. 타이틀 자연스러움
- H1이 사람이 실제로 검색할 문장인가
- 금지어(총정리, 정리, 완벽정리, ㅡ) 포함 여부
- 부자연스러운 단어 조합 탐지

### V11. 딥링크 유효성
- CTA 버튼의 URL이 HTTP 200을 반환하는가
- (선택) Playwright로 실제 접근 확인

### V12. 스포크 연결
- 관련 스포크 링크가 3개 이상 있는가
- 링크된 스포크가 실제 존재하는가

## 실행 순서 요약

```
사용자: /gov-write 기초연금

Step 1: npx tsx scripts/collect-keywords.ts "기초연금"
         → scripts/output/기초연금.json 생성

Step 2: 기초연금.json 읽고 Q1-Q4 분석
         → 스포크 목록 + 각 스포크별 H1/H2/컴포넌트 결정

Step 3: 사용자에게 구조 확인 요청
         "이 구조로 작성할까요?"
         → 승인/수정 후 진행

Step 4: 스포크별 글 작성
         → TSX 파일 생성

Step 5: verify-gov-article.js 실행
         → V1~V12 전수 체크
         → FAIL 항목 자동 수정

Step 6: 최종 리포트 출력
```
