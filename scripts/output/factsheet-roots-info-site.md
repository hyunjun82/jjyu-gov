# 팩트시트 — 뿌리를 찾아서 사이트 (roots-info-site)

## 0. 관할 확정

| 항목 | 내용 |
|---|---|
| 대상 | rootsinfo.co.kr (민간 사이트, 정부 서비스 아님) |
| 직계 기록 발급처 | 대법원 전자가족관계등록시스템 (가족관계증명서·제적등본) |
| 확인 방법 | Playwright 로 주소 5종 직접 접속 (2026-08-15) |

⚠ 이 글은 정부지원금이 아니라 **접속·발급 안내**다. 사이트가 민간이므로 정부 서비스처럼 쓰지 않는다.

## 0-B. 원문 캡처 확인 (직접 접속 실측)

- 캡처에서 확인한 것: 주소 5종을 각각 열어 상태코드·최종 URL·본문 길이를 쟀다. **https://www.rootsinfo.co.kr, https://rootsinfo.co.kr, https://m.rootsinfo.co.kr 세 곳 모두 20초 타임아웃**으로 연결되지 않았다. **http://www.rootsinfo.co.kr 와 http://rootsinfo.co.kr 는 200 응답**(각 192ms, 657ms)이었으나 **본문 텍스트가 0자**였다. HTML을 직접 받아보니 전체가 **1,541자**뿐이고 첫 줄이 `<meta http-equiv="refresh" content="0; url=https://www.rootsinfo.co.kr/info/home/">` 였다. 즉 http 로 들어가도 사이트가 스스로 https 로 즉시 넘긴다. 문서는 **frameset 구조**(`<frameset` 존재, `<iframe` 없음)이고, 프레임 목록에 `https://www.rootsinfo.co.kr/info/home/` 가 잡히지만 내용은 0자였다. 메타 태그에 `description: 족보 사이트, 성씨와 본관, 족보의 종류 유래, 촌수, 인구순위, 친인척 호칭법.` 과 `og:title: 뿌리를 찾아서` 가 들어 있어 사이트가 다루는 범위를 사이트 자신이 밝힌 문구로 확인할 수 있었다.
- **추가 실측(같은 날 15:58)**: 같은 주소를 다시 열었더니 이번에는 `https://www.rootsinfo.co.kr/info/home/` 로 넘어가 **페이지가 떴다**(문서 제목 '뿌리를 찾아서'). 그러나 몇 분 뒤 새 브라우저로 다시 열자 `ERR_CONNECTION_TIMED_OUT` 으로 실패했다. 즉 **접속이 됐다 안 됐다 하는 상태**다. 한 번의 실패를 두고 "사이트가 죽었다"고 쓰면 틀리고, 한 번의 성공을 두고 "정상"이라고 써도 틀린다. 본문은 이 반복 상태로 적는다.
- 버튼 목적지: 사이트 링크는 눌렀을 때 열릴 수도, 오류일 수도 있다. 그래서 버튼은 확실히 작동하는 대법원 전자가족관계등록시스템으로 보내고(200·제적·가족관계증명 노출 확인), 사이트 주소는 본문에 적기만 한다. 정부24는 plus.gov.kr 로 이동하며 제적 안내가 없어 버튼에서 뺐다.

## 2. 단서 조항

- http 가 200 이라고 해서 "사이트가 열린다"고 쓰면 오해다 — **이동 지시문 한 장**이다.
- 접속 장애는 시점에 따라 달라질 수 있다. 실측 시각을 함께 적는다.

## 5. 오해 소지 — 본문에서 푼 자리

1. "http로 넣으면 된다" → qa1에서 meta refresh 때문에 안 된다고 실측으로 설명
2. "내 조상이 나온다" → qa3에서 성씨·본관 단위임을 밝히고 직계는 제적등본으로 안내
3. 수록 규모를 단정 → 확인 못 해 본문에서 뺌
4. 접속 장애 원인 단정 → 원인은 밖에서 알 수 없다고 명시
