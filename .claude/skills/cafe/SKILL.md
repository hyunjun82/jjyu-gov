# /cafe — gov 글 → 카페 글 파일 → 검사 → 독립 검수 → 임시등록 (2026-09-29 확정)

사장님이 하는 말은 이것뿐이다: **"작성한 글 푸시하고 카페 글 작성해서 저장"**. 나머지는 이 순서대로 알아서 한다.
목표는 **리셋해도 같은 품질 이상**이 나오는 것 — 품질의 기준은 내 기억이 아니라 파일에 있다.

## 먼저 읽는다 (매번, 쓰기 전에)

1. `docs/cafe-post-baseline.md` — 품질 기준(구조·문체·사실 규칙·절차)
2. `reference/cafe/기초연금-확인조사-v2-기준.md` — 우리가 쓴 글 중 사장님이 "이 정도면 좋다"고 한 기준 원본
3. `reference/cafe/국민연금-기준소득월액-상한.md` — 경제 카페 홈판 글(사장님이 준 원본)
(미래에셋 매거진 idx=1319 는 문제해결 구조의 모범 — 필요하면 Playwright 로 열어 본다)

## 순서

1. **푸시** — 그날 쓴 gov 글을 커밋·푸시한다. pre-push 가 막으면 고쳐서 통과시킨다(`--no-verify` 금지). 사장님이 이 말을 했으면 푸시 승인으로 본다.
   Cloudflare 빌드가 끝나 글 주소가 열리는지 확인한다(카페 글 링크가 404이면 안 된다).
2. **대상 찾기** — 오늘 새로 쓰거나 고친 gov 글 전부. `scripts/cafe/.state.json` 의 `drafted` 에 없는 slug 가 대상이다.
   (스포크는 한 편씩. `scripts/cafe/legacy/` 는 옛 목록형 글 — 다시 쓰라고 할 때만 꺼낸다)
3. **카페 글 파일 작성** — `scripts/cafe/{slug}.md`. 재료는 **그 gov 글**(data/policies/*.ts, app/policy/**/content/**)과 1차 출처. 기준 문서의 구조대로 쓴다:
   제목(독자 일 + 핵심 사실 + 검색어, 자동완성 조회) → 서론 → **핵심 요약** → `링크:` → **답을 말하는 ■ 소제목** 4개 이상(아래 문단 3개 이상, 답 먼저) → 판단 기준 → **`예를 들어` 예시** → 오해 방지 → 마무리 → `링크:` → `태그:` 8~10개.
   - 합쇼체, 목록·표 없음, 전문 용어는 풀어 쓴다. 숫자는 gov 글에 있는 것만(계산 예시는 gov 공식으로).
   - gov 글에 재료가 부족하면 **카페 글을 억지로 부풀리지 않고** gov 글을 먼저 보강한다.
   - **썸네일 문구 한 줄**: 글 파일에 `썸네일: 큰 숫자 | 한 줄 제목 | 보조 문구 | 출처 | 라벨` 을 쓴다(큰 숫자는 글의 핵심 사실 하나, 예: "3년 → 2년"). 숫자·날짜는 글 본문에 있는 것만.
     이미지는 `node scripts/cafe/thumb.mjs scripts/cafe/{slug}.md` → `scripts/cafe/thumbs/{slug}.png`(1024×1024, 노랑 고정 틀 `templates/thumb-default.html`). 사진·정부 로고·인물 얼굴은 쓰지 않는다. 사장님이 임시등록 글에 끌어다 넣는다.
4. **검사** — `node scripts/cafe/check-cafe.mjs scripts/cafe/{slug}.md`. 통과할 때까지 고친다. (post.mjs 도 검사를 돌려 미통과 글은 올리지 않는다.)
5. **독립 검수** — 새 Agent 에게 파일과 기준 문서를 주고 "처음 읽는 독자로서 어색한 곳·풀이 없는 용어·답이 없는 소제목·gov 글과 어긋난 숫자"를 지적하게 한다. 지적을 반영한다. (내가 쓴 글은 내가 못 걸러낸다 — 사장님이 매번 읽지 않게 하는 장치)
6. **임시등록** — `node scripts/cafe/post.mjs --all` (로그인 대기 때문에 오래 걸리면 백그라운드로 돌리고 로그 파일로 진행을 본다).
   로그인이 풀려 있으면 사장님께 "열린 창에서 네이버 로그인(로그인 상태 유지 체크)" 을 부탁한다. 게시판 기본 '금융 경제', 다른 게시판은 `--board=정부지원금`.
7. **보고** — 임시등록된 편 수·제목, 검사·검수에서 고친 것, 못 올린 편(진단 `scripts/cafe/debug.json`)을 말한다.

## 하지 말 것

- 공개 등록(`--publish`) — 자동 승인 검사가 막는다. 우회하지 않는다. 사장님이 눌러야 한다.
- 검사기를 느슨하게 해서 통과시키기 — 오탐이면 규칙을 고치고 기준 원본이 여전히 통과하는지 본다.
- gov 글에 없는 사실·수치를 카페 글에 쓰기. 정부 이미지·정치인 얼굴 사진 넣기(저작권·오인 — 썸네일은 숫자 카드로).
- 이미 올린 글 중복 등록(`.state.json` 이 기억한다, 다시 하려면 `--again`).
- 프로세스를 이름으로 죽일 때 내 셸 명령 줄에 `post.mjs` 를 넣기(셸이 같이 죽는다). 창은 정상 종료되게 두고, 끌 때는 chrome 중 `remote-debugging-port=9333` 인자만 골라서 끈다. 강제 종료는 로그인 세션이 안 남는 원인이다.

## 화면이 바뀌어 막힐 때

`scripts/cafe/debug.json`·`debug.png` 를 보고 `post.mjs` 의 선택자를 고친다. 창은 디버그 포트 9333 으로 뜨므로 `chromium.connectOverCDP('http://127.0.0.1:9333')` 로 붙어 화면을 확인할 수 있다.
