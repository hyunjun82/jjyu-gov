# /gov-write — 정부지원금 콘텐츠 자동 생성

키워드 `$ARGUMENTS`를 받아 7단계 파이프라인을 자동 실행한다.

---

## Phase 0: 최신 데이터 검색 (생략 금지)

**글 작성 전 반드시 WebSearch로 당일 기준 최신 데이터를 확인한다.**
정부 정책은 수시로 바뀌므로, 기존 코드에 있는 숫자를 신뢰하지 않는다.

### 필수 검색 (3회)
```
WebSearch: "2026년 {keyword} 금액 기준 인상"
WebSearch: "2026년 {keyword} 선정기준액 소득인정액"
WebSearch: "{keyword} 최신 변경사항 개편"
```

### 추출 항목 (정책별로 다르지만, 아래는 공통)
- 지급 금액 (단독/부부/가구별)
- 선정기준액 (소득인정액, 중위소득 등)
- 올해 인상 내역 및 인상률
- 공제 기준 (근로소득공제, 재산공제 등)
- 신규 조건 또는 폐지된 조건
- 시행일, 지급일

### 대조 규칙
1. 검색 결과 숫자와 기존 `data/policies/{keyword}.ts` 숫자가 다르면 → **기존 데이터 수정 먼저**
2. 검색 결과가 불확실하면 → 보건복지부·정책브리핑·복지로 등 공식 출처 WebFetch 시도
3. 공식 소스에서도 확인 불가하면 → 사용자에게 "이 숫자가 맞는지 확인 필요" 보고
4. 수집된 최신 데이터를 **Phase 5 글 작성의 유일한 소스**로 사용

## Phase 1: 실제 검색어 수집

Playwright로 4개 포털에서 실제 사용자 검색어를 수집한다.

```bash
npx tsx scripts/collect-keywords.ts "$0"
```

수집 결과를 `scripts/output/$0.json`에서 읽는다.
- 총 검색어 수 확인 (30개 미만이면 동의어 추가 후 재수집)
- 의도별 분류 확인: info / condition / action / compare / calculate / confirm / question

PAA가 0개면 구글에서 "$0" 검색 후 "관련 질문" 섹션을 Playwright로 직접 수집한다.

---

## Phase 2: Q1-Q4 필수 사고

수집된 검색어를 읽고, 아래 4개 질문에 **구체적 한 문장**으로 답한다.

### Q1. 이 키워드를 검색하는 사람은 지금 어떤 상황인가?
- 수집된 검색어 패턴에서 **실제 검색 상황 3가지 이상** 도출
- 각 상황이 별도 스포크가 될 수 있는지 판단
- "궁금해서", "알고 싶어서" 같은 일반적 답 금지
- 이 답이 **서론 첫 문장**이 된다

### Q2. 이 글을 읽고 나서 할 수 있어야 하는 행동은?
- 각 스포크별 **최종 행동 1개** 특정
- 그 행동의 **마지막 클릭 URL** 특정 → 딥링크 CTA 목적지
- 이 답이 **CTA 버튼 텍스트**가 된다

### Q3. 행동하려면 반드시 알아야 하는 정보는?
- 수집 검색어 중 해당 스포크 의도에 속하는 것 전부 나열
- 이것이 **H2 개수와 깊이**를 결정
- 수집 검색어에 없는 H2는 만들지 않는다

### Q4. 이 정보를 가장 잘 전달하는 형태는?
- 아래 **15개 컴포넌트** 중 의도에 맞는 것 선택

## Phase 3: 타이틀·H2·스포크 구성

### 타이틀 규칙
1. **H1 = 실제 수집된 검색어** 그대로 (최소 수정)
2. 부자연스러우면 **동의어로 교체** (수집된 동의어만 사용)
3. Q2 행동 결과를 자연스럽게 이어 붙일 수 있으면 붙인다
4. **금지**: 총정리, 정리, 완벽정리, ㅡ, —, –, 파이프(|)

### H2 규칙
1. **반드시** `scripts/output/$0.json`의 수집 검색어 또는 PAA에서 가져온다
2. 내가 만든 소제목 **금지** — 수집 검색어에 없으면 H2로 쓰지 않는다
3. 검색어가 질문형이면 **질문 그대로** H2로 사용
4. 검색어가 명사형이면 자연 질문으로 변환 ("기초연금 재산기준" → "재산이 얼마까지면 받을 수 있나?")
5. H2 순서 = 검색빈도 추정 우선순위 (여러 포털에서 중복 등장한 것 먼저)

### 스포크 분리 기준
- 검색 의도가 **다르면** 별도 스포크
- 같은 의도 안에서 수집 검색어가 **5개 이상**이면 별도 스포크 고려
- 하나의 스포크에 H2는 **3~6개**
- 허브 페이지의 스포크 목록에 추가

### 구조 확인
스포크 목록과 각 H1/H2를 **사용자에게 보여주고 승인**을 받은 후 Phase 4로 진행한다.
```
[스포크 구조 확인]
허브: {keyword}
스포크 1: {H1} (수집 검색어: {원본})
  H2-1: {제목} (출처: {네이버/구글/빙/다음})
  H2-2: {제목} (출처: {포털명})
  ...
스포크 2: ...
```

## Phase 4: 컴포넌트 자동 선택

### 15개 컴포넌트

| ID | 이름 | 트리거 조건 |
|----|------|-----------|
| C01 | 자격 체커 | condition + "받을 수 있나", "자격", "대상" |
| C02 | 소득인정액 계산기 | calculate + "소득인정액", "계산" |
| C03 | 지급액 시뮬레이터 | calculate + "얼마", "금액", "수령액" |
| C04 | 비교표 | compare + "차이", "vs", "다른" |
| C05 | 기준표 | condition + "기준", "이하", "이상", "한도" |
| C06 | 금액표 | "금액", "단독", "부부", "가구" |
| C07 | 서류 체크리스트 | action + "서류", "준비물", "가져갈 것" |
| C08 | 신청 경로 탭 | action + "신청", "어디서", "방법" |
| C09 | 타임라인 | "절차", "순서", "언제", "지급일" |
| C10 | 경고 박스 | "제외", "안 되는", "주의", "실수" |
| C11 | 상황 분기 | "~하면", "~인 경우", "~이면" |
| C12 | 딥링크 CTA | 모든 스포크 (Q2 행동의 마지막 클릭) |
| C13 | 요약 카드 | 모든 스포크 최상단 (5초 답변) |
| C14 | FAQ 아코디언 | PAA 질문 3개 이상 |
| C15 | 관련 스포크 링크 | 모든 스포크 하단 |

### 선택 로직
```
필수: C12 + C13 + C14 + C15
condition → +C01 +C05
calculate → +C02 or C03 +C06
action    → +C07 +C08
compare   → +C04
confirm   → +C11
제외/주의 키워드 → +C10
절차/일정 키워드 → +C09
```

## Phase 5: 글 작성

### 파일 구조
- 허브 데이터: `data/policies/{keyword}.ts`
- 스포크 콘텐츠: `app/policy/[id]/[spoke]/content/{keyword}/{slug}.tsx`

### 글 구조 (모든 스포크 공통)
```
[기] 서론 — Q1 상황 공감 첫 문장
[승] C13 요약카드 (answer-box) — 5초 핵심 답변
[전] H2 섹션들 — 수집 검색어 하나에 하나씩 답변
     각 H2 안에 Phase 4에서 선택된 컴포넌트 배치
     광고 슬롯: H2 2~3개마다 1개 (<div className="ad-slot">광고 영역</div>)
[결] C12 딥링크 CTA 버튼
     C14 FAQ 아코디언
     C15 관련 스포크 링크
```

### 문체 규칙
- "~에 대해 알아보겠습니다" 금지
- "또한", "결론적으로", "다양한", "매우 중요" 금지
- 3문장 연속 같은 어미 금지
- 3문장 연속 같은 단어 시작 금지
- 전문용어 뒤 반드시 괄호로 쉬운 설명

### 소스 규칙
- 모든 숫자/기준은 gonggam.korea.kr 또는 공식 소스에서만
- 소스에 없는 정보 → "소스 없음" 보고 후 사용자에게 요청
- sources 배열에 출처 URL 반드시 기재

### SpokeData 인터페이스
```typescript
export interface SpokeData {
  h1: string;          // Phase 3에서 결정된 타이틀
  breadcrumb: string;
  description: string; // 메타 디스크립션 (수집 검색어 자연 조합)
  datePublished: string;
  dateModified: string;
  Content: React.ComponentType;
  faqData: { q: string; a: string; source: string; sourceUrl: string }[];
  sources: { name: string; url: string }[];
}
```

## Phase 6: 자동 검증

글 작성 완료 후 Stop 훅이 자동 실행하여 12개 항목을 검증한다.

| # | 체크 | PASS 기준 |
|---|------|----------|
| V1 | 타이틀 검색어 일치 | H1 메인 KW가 수집 검색어에 존재 |
| V2 | H2 출처 | 모든 H2가 수집 검색어/PAA에 근거 |
| V3 | Q1 공감 | 서론 첫 문장이 독자 상황 공감 (제3자 시점 FAIL) |
| V4 | Q2 행동 | CTA 버튼 존재 + 실제 URL |
| V5 | Q3 완결 | 의도별 수집 검색어가 본문에서 답변됨 |
| V6 | Q4 컴포넌트 | 의도에 맞는 필수 컴포넌트 사용 |
| V7 | 요약카드 | answer-box가 최상단에 존재 |
| V8 | 소스 일치 | 숫자/기준이 공식 소스와 일치 (WARNING) |
| V9 | 문체 | 금지어, filler, 같은 어미 3연속 없음 |
| V10 | 타이틀 자연 | 금지어(총정리 등) 미포함, 대시 미사용 |
| V11 | 딥링크 유효 | CTA URL이 https:// 형식 |
| V12 | 스포크 연결 | 관련 스포크 링크 2개 이상 |

FAIL 항목이 있으면 **자동 수정 후 재검증**. 3회 시도 후에도 FAIL이면 사용자에게 보고.
