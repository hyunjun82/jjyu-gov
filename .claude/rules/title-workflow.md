```
   — 소제목은 실검색어 그대로의 PAA 질문. 행동(청구 방법)은 최상단
   — ★ 버튼 목적지(딥링크)를 Playwright 로 먼저 연다. 로그인·인증이 걸리는지,

4. 그 사실 위에서 타이틀 → 서론·버튼 문구 → 본문 순으로 쓴다
   — 서론(heroHook)은 타이틀과 일치. 타이틀이 나열한 항목을 서론에서 풀버전으로 편다
```

**더 없다.** 이 4단계 밖의 것을 먼저 하면 순서가 뒤집힌 것이다.

## 2단계 구성표 — 이 꼴로 만들어 승인받는다 (정본)

타이틀 캡처와 함께 **이것도 무조건 본다.** 이 규칙이 자동 로드되므로 따로 열 필요 없다.

| 위치 | 소제목 | 버튼 |
|---|---|---|
| **hero** | (서론) 타이틀이 나열한 항목을 풀버전으로 편다 | **← 상단 버튼 1개 (승부처)** |
| qa 1 | **{주제} 청구 방법** ← 행동, 간결하게. **최상단** | 바로 위 hero 버튼이 받음 |
| qa 2 | {주제} 되나요? | |
| qa 3 | {세부항목1} 되나요? | **← 슬롯** |
| qa 4 | {세부항목2} 되나요? 한도는 몇 번까지일까요? | |
| qa 5 | {세부항목3} 되나요? | **← 슬롯** |
| qa 6 | {추가 궁금증} 달라지나요? | **← 슬롯(마지막)** |

읽는 법:
- **버튼은 qa 인덱스 2·4·마지막에만 렌더된다** (`SpokeClient.tsx` 171행 `[2, 4, qa.length-1]`).
  다른 자리에 `act` 를 달면 화면에 안 나온다. 개수를 정한 뒤 슬롯을 맞춘다.
- **클릭은 최상단에서 일어난다** — Clarity 실측 상단 50~57% / 중간 0~1클릭.
  그래서 행동(청구 방법)이 qa 1이고, hero 버튼이 그 바로 위에서 받는다.
- 소제목 문구는 **수집한 실검색어 그대로**. "침 맞은 건 되나요?" 같은 창작 금지,
  `한의원 침치료 실비`(빙) 처럼 실제로 검색된 말을 쓴다.
- 개수는 타이틀이 정한다. 위 표는 6개 예시일 뿐 고정이 아니다.

## 타이틀 — 캡처를 열지 않고 지으면 매번 틀린다

이 규칙은 스포크·정책 파일을 건드리면 자동 로드된다.
버튼 규칙(`action-copy.md`)이 항상 로드되는 것과 같은 자리다.

## 왜 이 파일이 생겼나 (2026-08-08)

타이틀 규칙은 CLAUDE.md 산문에만 있었다. (2026-08-23: gov-write 스킬은 삭제됐다)
그런데 **SKILL.md 는 Skill 도구를 호출해야만 로드된다.** 사장님이 자연어로
"글 써줘" 하시면 스킬은 안 열린다. 그래서 캡처를 보라는 지시가 실행 경로에
아예 들어오지 않았고, 매번 건너뛰었다. 지적받고 CLAUDE.md 에 적고, 또 건너뛰고,
push 시점 리마인더를 만들고, 또 건너뛰었다 — 자리를 잘못 골랐기 때문이다.

버튼 규칙은 `action-copy.md` 로 항상 로드돼서 그나마 지켜졌다. 같은 방식으로 옮긴다.

## 1. 주제를 받으면 이것부터 — 캡처 5장을 Read

```
reference/titles/대출 타이틀.png
reference/titles/보험타이틀.png
reference/titles/생활타이틀.png
reference/titles/세금 타이틀.png
reference/titles/연금 타이틀.png
```

주제와 가장 가까운 1장은 반드시 연다. **타이틀 후보를 입에 올리기 전에.**
열었으면 이 두 줄을 채운다. 못 채우면 안 연 것이다.

- 어느 캡처의 어느 줄을 봤나 (그 타이틀 그대로 옮겨적기)
- 그 구조를 왜 고르나 (한 문장)

## 2. 실검색어 조각으로만 조립

`npx tsx scripts/collect-keywords.ts "{주제}"` 결과 파일 안에 **실제로 있는 문자열**로만
조립한다. 머리로 지은 단어는 넣지 않는다. 패턴은 `docs/title-corpus-kb.md` ①~⑨.

## 3. 구조 — 이게 전부다 (2026-08-08 사장님 확정)

```
타이틀 = 롱테일 메인키워드 3개쯤이 들어간 한 줄
   ↓
소제목 = 그 키워드마다 질문형(PAA) 하나씩
   ↓
답     = 사용자 중심 문제 해결
```

**소제목 개수는 타이틀이 정한다. 고정 7개가 아니다.**
타이틀이 3개를 약속하면 3~4개, 5개를 약속하면 5개. 사용자가 실제로 더 궁금해하는
게 있으면 그때 추가한다. **채우려고 붙이지 않는다.**

- 예: "한의원 실비 청구되나요? 침 추나 한약 어디까지 되는지"
  → 키워드 4개(한의원 실비 / 침 / 추나 / 한약) → 소제목 4~5개면 충분

⚠ 게이트가 원래 `qa[] ≥ 7` 고정이라 억지로 채웠다(실손 스포크 24개가 전부 7개).
2026-08-08 하한을 3으로 낮췄다. 개수가 아니라 **덮었는지**가 기준이다 — 타이틀이 약속한
세부키워드마다 소제목 하나. 이건 검사기가 없다. 소제목을 PAA 문장 그대로 쓰고 그 조각으로
타이틀을 조립하면 어긋날 수가 없다(§3 순서).

소제목을 먼저 확정하고, **그 질문들에 이미 등장한 단어**로 타이틀을 조립한다.
순서를 뒤집으면 타이틀↔소제목이 반드시 어긋난다.

## 4. 종결 — `~법` 금지

허브 745개 중 **387개(51.9%)가 이미 "법"으로 끝난다.** 같은 어미가 사이트 전체에
반복되면 포털이 기계 생성으로 볼 여지가 생긴다.
물음형·시나리오형으로 끝낸다: "며칠 받나", "놓치면 어떻게 되나", "1분이면 끝".

## 5. 모수를 좁히는 자격 숫자 금지

"19년 6개월 채우면" 같은 자격 숫자는 대상을 잘라낸다. 본문 소제목으로 내린다.
이득 숫자(40만원 받기)는 모두를 부른다.


## 6. 새 스포크는 템플릿에서 시작한다 (2026-08-11 신설)

```
npx tsx scripts/new-spoke.ts --spec scripts/output/spec-{slug}.json
```

**왜**: 하루치 게이트 차단을 축별로 세어보니 "버튼 슬롯"이 7건으로 1위였다.
act 를 내용상 어울리는 카드에 넣었는데 화면에는 qa 인덱스 **2·4·마지막**에만
렌더돼(`SpokeClient.tsx` 171행) 매번 되돌려 옮겼다. 나머지 차단 사유도
faqData 의 `source`·`sourceUrl` 누락, 금지어(대부분·대개·경우가 많·흔합니다),
루트 URL 처럼 **미리 자리를 잡아두면 생기지 않는 것**들이었다.

검사기를 늘리지 않는다. 틀릴 수 없는 뼈대를 쓴다.
